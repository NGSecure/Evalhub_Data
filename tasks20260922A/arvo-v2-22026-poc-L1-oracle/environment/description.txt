Open vSwitch (MSan build): the ODP fuzz target's key/mask round trip re-encodes a previously-decoded tunnel key back into a netlink flow-key attribute, and a use-of-uninitialized-value warning fires while a boolean guard inspects two GTPU tunnel-option byte fields (a flags byte and a message-type byte) on the in-memory tunnel-key struct to decide whether a nested GTPU-options attribute needs to be written out. Root cause: the ODP string-format key/mask parser that fills in these two GTPU sub-fields keeps its scratch flags/message-type locals (one pair for the key side, one pair for the mask side) uninitialized on entry and only assigns each pair conditionally, gated on whether the corresponding textual sub-field ('flags=' / 'msgtype=') actually appears in the input string. When the enclosing GTPU group is closed with one of those sub-fields absent, the parser still unconditionally copies its local scratch bytes into the caller's output key and mask structs, so the mask-side message-type byte carries forward raw, never-assigned stack memory instead of a defined value. That uninitialized byte is then copied verbatim into a netlink attribute buffer when the mask is serialized for the flow's string-form representation, decoded back out of that same attribute into the tunnel-key struct's message-type field on the next parse of the flow, and only surfaces as a MemorySanitizer report much later when the re-encoding step's guard condition reads it back to decide on the nested-attribute output.
