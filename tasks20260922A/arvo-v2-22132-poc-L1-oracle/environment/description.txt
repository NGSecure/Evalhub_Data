Fluent Bit's logfmt log-line parser (ASan build, exercised via its logfmt parsing fuzz target) triggers a one-byte heap-buffer-overflow read when a quoted field being unescaped ends in a single, unpaired backslash with nothing after it. The value-unescaping routine that the logfmt parser calls for every quoted field walks the input byte by byte, stopping only on a NUL terminator or a separate running byte counter -- it never checks its scan pointer against the actual end of the allocated input buffer. Once it consumes the buffer's very last byte and finds that byte to be a backslash, it unconditionally peeks one further byte ahead to decide which escape character follows, before any escape-kind dispatch or digit decoding ever runs. That peek lands one byte past the end of the heap allocation whenever the unescaped field's final character is a dangling backslash with no following character in the buffer at all.
