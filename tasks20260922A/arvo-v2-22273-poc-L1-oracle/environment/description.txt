In wabt (ASan), parsing a WebAssembly module's custom "linking" section takes the function index carried by one of its symbol-table entries and uses it directly to index into the array of functions the reader has already parsed from the module, without first checking that index against how many functions the module actually declares. A linking section crafted with an out-of-range function symbol index causes that unchecked index to read past the end of the function-pointer array, yielding a garbage pointer instead of a real function object. The very next step dereferences this garbage pointer to check whether the function already has a name, so the crash surfaces as a wild-address read deep inside the C++ standard-library string implementation rather than at the out-of-bounds indexing site itself.
