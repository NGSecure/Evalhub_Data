nDPI (libFuzzer ASan build): feeding a UDP packet whose source or destination port equals the well-known H.323 call-signaling port routes the packet into the H.323 protocol detector's broadcast-signature check. Root cause: that check inspects several fixed byte offsets of the packet's payload (the first, second, fifth and sixth bytes) and compares them against a magic broadcast pattern, but the code guards entry only on the port match and never verifies beforehand that the payload actually contains that many bytes. Because the comparisons are chained with logical AND and evaluated left to right, a payload as short as a single byte can still pass the first comparison if that lone byte happens to equal the expected constant; evaluating the next byte comparison then reads one byte past the end of the allocated payload buffer, producing a 1-byte heap-buffer-overflow read.
