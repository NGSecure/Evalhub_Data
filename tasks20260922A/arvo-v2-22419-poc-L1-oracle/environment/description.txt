A crafted UDP Kerberos AS-REQ packet triggers a 1-byte heap-buffer-overflow read while nDPI is parsing the packet's principal-name (cname) field.

Root cause: after extracting the cname field, the dissector computes a byte offset into the packet payload for the realm field that follows, using simple pointer arithmetic on the cname length and the cname's own offset. This computed offset is never checked against the payload length before use. The code then loops (up to 14 times) looking for the next ASN.1 tag byte (0x1b): on each iteration it indexes the payload at the current offset and, if the byte isn't the tag, advances the offset by one. Because the starting offset can already sit at or beyond the true end of the payload, this scan indexes past the end of the heap-allocated payload buffer before any bounds check is ever applied, producing a 1-byte out-of-bounds read.
