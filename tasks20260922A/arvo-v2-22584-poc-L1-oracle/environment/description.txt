stb's baseline JPEG decoder (UBSan build, reached via the header-only info-query entry point that parses a JPEG file's markers without fully decoding pixels) builds a Huffman code table while handling a Define-Huffman-Table marker: the marker supplies 16 byte-sized counts, one per code length, and a routine sums them into a total symbol count before handing that count array off to a table-building helper. Root cause: neither the marker handler nor the table-building helper ever checks that this total stays within the 256-symbol ceiling a valid JPEG Huffman table can have (one byte-sized symbol per code, at most 256 distinct symbols total); the table-building helper instead trusts the attacker-controlled per-length counts outright and walks them in a nested loop, writing one entry per counted symbol into a fixed 257-slot table via a running index that only ever increments. A crafted marker whose 16 declared counts sum past that ceiling drives the running index one slot beyond the table's last valid entry, so the loop's next write lands outside the array and its bounds check trips.
