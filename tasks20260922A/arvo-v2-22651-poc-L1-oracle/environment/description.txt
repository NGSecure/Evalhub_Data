stb's image-decoding fuzz target (ASan build): decoding a crafted TGA (Truevision Targa) image with an indexed/color-mapped pixel format and a color-map length field of zero causes a heap-buffer-overflow read of a few bytes just past a color-map buffer that ends up holding no usable bytes at all. Root cause: the loader trusts the color-map length field enough to size the color-map allocation from it (an effectively empty allocation when the field is zero) but never rejects that zero-length case up front; the per-pixel index-bounds check that is supposed to clamp an out-of-range color-map index back to a safe value uses a "greater-or-equal" comparison against that same zero length, so instead of ever flagging an index as invalid it always resets it to index 0 and lets decoding continue — the per-pixel color lookup then reads the pixel's component bytes starting at that "safe" index 0 inside the empty buffer, running a few bytes past its end for every pixel of the image.
