LibRaw's Canon CR3 (an ISO-BMFF/MP4-style nested atom/box container) metadata walker recurses through the file's box tree and tracks which numbered image/video track it is currently positioned inside using a signed counter that the caller initializes to an invalid sentinel value before any track-container box has been seen. That counter is only ever advanced, and only ever bounds-checked against its *upper* limit, at the moment a box literally named as a track container is encountered; nothing guards the case where the counter is still sitting at its initial sentinel because no such box has been walked yet. After finishing the handling for every box the parser visits, it unconditionally consults a fixed-size, statically sized array of per-track metadata (indexed by that same counter) to decide whether the track-level offset/size fields look populated enough to recurse into further track sub-boxes. A crafted file whose very first few boxes reach this metadata check before the counter has ever been incremented past its sentinel causes the array lookup to be computed with a negative index, landing one element before the start of the array — an out-of-bounds read that a sanitizer instrumented build (UBSan) flags as an invalid array index rather than a segfault, since the read memory happens to be mapped.
