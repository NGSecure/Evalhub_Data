LibRaw (MSan build): decoding a malformed raw file that gets misidentified as a Kodak SMAL-camera capture triggers a use-of-uninitialized-value warning inside the SMAL decoder's post-decode gap-patching pass. Root cause: the format-detection fallback used whenever no camera make string is recognized routes the file into the SMAL v9-generation decoder instead of rejecting it outright; that decoder allocates its raw pixel buffer with a plain, non-zeroing allocator, and for a sufficiently degenerate/short input, its interpolation pass -- meant to patch a small number of sensor cells the decode step legitimately skips -- ends up treating several cells that were never actually decoded as valid neighboring values, so it reads straight out of unwritten heap memory when computing each replacement pixel.
