The Fraunhofer FDK AAC decoder's USAC/ACELP time-domain path (aacDecoder_DecodeFrame, ASan build) suffers a 4-byte stack-buffer-overflow read while filtering the pitch (long-term-prediction) excitation for a concealed ACELP subframe: when a subframe must be concealed because the bitstream signals frame loss, the pitch lag used for concealment is carried over from the previous frame's stored value and is only bounds-checked against the current frame's maximum-pitch-lag limit (which itself varies with the active sample-rate/frame-length configuration); the replacement value written back into the persisted pitch-lag state when that check trips goes through a narrowing cast that discards its high bits, so whenever the intended clamp value is larger than a single byte -- which happens for configurations that allow a larger maximum pitch lag -- the stored lag silently wraps around to a much smaller number. Because the interpolation routine's read/write span over its fixed-size per-frame excitation scratch buffer shifts further toward (and, for a small enough lag, past) the buffer's far end as the pitch lag shrinks, this wrapped-around, abnormally small lag makes the routine walk one element beyond the end of that buffer on the very next concealed subframe, producing the out-of-bounds read.
