rnp (ASan build), dumping an OpenPGP ASCII-armored packet stream: while scanning the input bytes that immediately precede a detected armor header line for stray non-whitespace content, each raw byte is used as an index into a fixed 256-entry lookup table that classifies base64-alphabet characters. Root cause: a byte with its high bit set (a non-ASCII / high-value byte occurring before the header line) is sign-extended from a signed `char` to a negative `int` before that table lookup, so the read lands one or more bytes before the start of the table, triggering a global-buffer-overflow read.
