rnp (ASan build), dumping an OpenPGP ASCII-armored packet stream: after consuming the base64-encoded body, the reader decodes the trailing base64-encoded trailer checksum line character-by-character by feeding each raw input byte into the same 256-entry base64-alphabet classification table used elsewhere while parsing armored input. Root cause: a trailer-line byte with its high bit set is sign-extended from a signed `char` to a negative `int` before that table lookup, so the read lands one or more bytes before the start of the table, triggering a global-buffer-overflow read.
