SleuthKit's FAT `fls` directory-listing fuzz target (ASan build): reconstructing the synthetic "orphan files" directory for unallocated-but-still-referenced inodes triggers a strncpy-param-overlap abort. Root cause: after the orphan scan finishes, a cleanup pass removes entries that turned out to already be reachable from a subdirectory by overwriting the duplicate slot with the array's current last live entry and then shrinking the live-entry count by one; this overwrite is done by copying one directory-entry/name record's fields, including a pointer to its heap-allocated name buffer, onto another record. The code guards against doing this copy only when the whole array holds a single live entry, but it never checks whether the *specific* duplicate slot picked for removal already *is* that last live entry; when it is, the "source" and "destination" records of the copy are the exact same object, so the string field is effectively copied onto itself, and the underlying strncpy() call receives fully-overlapping source and destination pointers, which ASan's interceptor flags and aborts on.
