nDPI's Kerberos AS-REQ (message type 0x0A) parser, exercised by the UDP packet-processing fuzz target, decodes the request's client-name (cname) field into a fixed 48-byte on-stack buffer, clamping the attacker-supplied length byte to the buffer's capacity before each copy. When the decoded name equals one of two recognized alias strings, the parser treats it as an indirection: it advances past the alias and re-reads a fresh length byte directly from the packet so the alias-following step can repeat and decode the real name. This re-read loop is capped at two iterations. If the alias match happens on the last permitted iteration, the loop exits immediately after the length variable is reloaded from the packet — before the copy-and-clamp step that would normally re-bound it runs again — so the fresh, still up to 255-valued length survives into later code that reuses it, unchecked, to index the final decoded character of that same 48-byte buffer (to test whether the name ends in '$'). AddressSanitizer reports the resulting read as touching memory outside the buffer's live scope; the out-of-bounds offset happens to land inside the storage of an unrelated, already-exited local string belonging to a sibling message-type branch of the same parsing routine, because the compiler reuses stack slots across non-overlapping lexical blocks in the (optimized) build. Root cause: the length value gating that final buffer-index expression is re-derived from untrusted packet bytes on the loop's terminal iteration without ever passing through the same bounds clamp every other use of that value receives.
