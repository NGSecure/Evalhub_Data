nDPI (MSan build): feeding a crafted UDP packet through the Kerberos protocol dissector triggers a use-of-uninitialized-value read while the dissector extracts the client-principal name (cname) component from an AS-REQ/AS-REP-style message body. Root cause: the dissector declares a small fixed-size local buffer on the stack to hold the decoded cname text, together with a companion length variable that is supposed to be set from the ASN.1-style length field of the cname component before anything is copied into or read out of that buffer. On the malformed/edge-case packet shape the fuzzer found, the code path that walks the Kerberos name-component structure reaches the point where the cname buffer's contents get consumed (lower-cased and copied out into the flow's tracked hostname) without ever having gone through the branch that actually bounds-checks the length and populates the buffer from packet bytes first. Because the buffer and its length control variable were never given an explicit default value at declaration time, whatever indeterminate bytes happened to be sitting in that stack slot from a previous function's frame are treated as already-decoded cname data and read/copied downstream, which is what MemorySanitizer flags. No write-side memory corruption is involved — the packet only needs to steer the parser into the "component present but not walked/populated" branch rather than the normal length-checked copy path.
