Oniguruma's regex-compile fuzz target (ASan build) aborts with a stack-buffer-overflow write while expanding a pattern's Unicode case-fold candidates during compilation: for a multi-character folded string, the compiler enumerates every combination of alternate code points for each folded character position and stores each combination into a fixed-size stack array of candidate entries, sized to hold every combination except the one combination that reproduces the string's original, unfolded code points (that one is meant to be recognized and dropped, since it isn't really an "alternate"). The loop writes the current combination's fields into the array slot at the running candidate count and only afterward compares it against the original code points, skipping the count increment (but not the write) when they match. Because the write always happens before the redundancy check, if the combination that duplicates the original code points happens to be the very last one produced by the nested enumeration, every combination before it has already advanced the slot index to one past the array's last valid entry, so the discard-bound write for that final combination lands one slot beyond the buffer's declared capacity, corrupting adjacent stack memory with a 4-byte value.
