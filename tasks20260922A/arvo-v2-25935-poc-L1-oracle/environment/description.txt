OpenSC's synthetic PKCS#15 profile emulation for a family of Italian national-ID smart cards, exercised through the PKCS#15 reader fuzz target (ASan build): once the emulator locates and reads the card's dedicated "personal data" record among its synthesized data objects, it hands that record's raw byte buffer straight to a small helper that treats the record's leading fixed-width run of bytes as an ASCII-hex-encoded total-length field. To turn that leading run into an integer, the helper copies it into a small local stack buffer with a bounded string-copy call sized to the header's declared byte width plus one extra byte for a trailing terminator, and it always requests that many bytes from the source regardless of how large the record's own underlying allocation actually is. The record's raw buffer, though, is allocated by an earlier DER-decoding step to match only the exact number of bytes the record actually carries, with no slack reserved beyond that. So a record whose real content is exactly as short as, or shorter than, the header's own declared width leaves no spare byte past the end of that allocation, and the copy — which always asks for one more byte than the header width to make room for the terminator — reads one byte past the end of the heap allocation before the routine has even finished interpreting the header value, let alone walked any of the record's later per-field structure (name, dates, and so on). Reaching the crash needs nothing more than steering the emulation to this one record and making its raw content sit at or under this small fixed byte count; none of the record's subsequent fields have to be correctly constructed for the read to go out of bounds.
