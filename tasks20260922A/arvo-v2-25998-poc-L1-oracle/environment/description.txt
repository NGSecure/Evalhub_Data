OpenSC's IDPrime/Gemalto smart-card driver (ASan build), exercised through the PKCS#15 fuzz target's card-binding path: when a freshly selected file's FCI response begins with this driver's own two-byte marker for a compressed on-card certificate, the driver's read routine declares a fixed-size buffer on its stack sized for the largest single extended-APDU response, and checks that capacity against the number of bytes its caller originally asked it to read — but then reads a different, larger quantity into that same buffer: a file-size value cached straight from the earlier FCI response, which is never itself checked against the buffer's capacity. This unchecked, card-declared length is passed down through the ISO 7816 transmission layer as the total size of the caller's response buffer; the layer's length-clamping logic only shortens the first single command/response exchange, not that declared total, so the higher-level GET-RESPONSE continuation loop that assembles a multi-part card response keeps copying further card-supplied chunks into the same buffer until it believes the full (unbounded) declared length has been satisfied — overflowing the fixed stack buffer once the FCI-declared file size exceeds its real capacity. The trigger condition is fairly loose: no valid certificate content, signature, or specific PKCS#15 object layout is required, only a file-selection response carrying the two-byte compressed-certificate marker plus an oversized declared size, reached while OpenSC's binding logic auto-tries this driver's profile against a fuzzed card image.
