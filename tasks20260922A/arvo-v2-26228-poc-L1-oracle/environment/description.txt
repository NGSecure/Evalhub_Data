In c-blosc2 (AddressSanitizer), decompressing a different crafted chunk that also declares multiple compressed data segments inside a block causes a SEGV from a wild, unmapped-address read, this time before any decompression library is even reached. The same unreliable, one-time pointer-based bounds check on each segment's attacker-controlled compressed-length field can let one segment's oversized length push the input cursor arbitrarily far past the real end of the buffer without being caught; the very next loop iteration then dereferences that cursor to pull out the following segment's 4-byte length field, landing on completely unmapped memory rather than a valid heap redzone and crashing with a raw SIGSEGV instead of a reported heap-buffer-overflow. The fix replaces the pointer-based check with a running remaining-bytes counter that is decremented and re-validated before every read, so an out-of-range length is rejected immediately instead of being allowed to move the cursor off the end of the buffer.
