Summary: In libsrtp, creating an SRTP stream with one of the NULL-cipher crypto policy presets triggers a heap-buffer-overflow READ of 30 bytes during master-key initialization, because the preset declares a master-key length shorter than what the key-copy routine actually reads.

Root cause: Two of the built-in crypto-policy presets for the NULL cipher (paired with HMAC-SHA1-80 and with NULL auth respectively) set their key-length field to 16 bytes -- the raw AES key size alone, without the additional salt bytes. However, stream/key initialization always treats a master key as "cipher key + salt" using the same fixed-size layout as the AES-ICM-128-with-salt suite (16-byte key + 14-byte salt = 30 bytes total), independent of which policy preset selected the NULL cipher. Callers (including the fuzz harness) allocate the input master-key buffer using the preset's declared 16-byte length, but the internal key-setup memcpy unconditionally copies the full 30-byte key+salt layout out of that buffer. Because the source buffer is only 16 bytes, the copy reads 14 bytes past its end, producing the reported heap-buffer-overflow read of size 30 from a 16-byte allocation. The bug is a mismatch between a too-small declared/allocated key length and a larger, hard-coded expected length used at copy time -- the fix enlarges the declared key length (from 16 to the standard 30-byte key+salt constant) so the two now agree, rather than shrinking the amount copied.

fix_commit judgment: fix_commit (f1d1e57a49dca345e086e01b5fccc44e723221e0) matches the crash. The patch changes exactly the two NULL-cipher policy-setter functions responsible for the undersized preset, in the same source file where the crash occurs, replacing the hard-coded 16-byte key-length assignment with the standard 30-byte AES-ICM-128-with-salt key-length constant in both. This directly closes the gap between the declared/allocated 16-byte master-key buffer and the 30-byte read performed during key initialization, which is exactly the mechanism observed in error.txt (a 30-byte READ overflowing a 16-byte heap allocation). No indication the fix targets an unrelated issue.
